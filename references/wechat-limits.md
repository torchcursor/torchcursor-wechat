# 微信粘贴红线与已知回落项

本文件记录的事实来自 2026-09 的实测与官方文档核查（微信公众号图文编辑器）。规则会变，遇到反例以你的实测为准，并回来更新本文件。

---

## 一、为什么必须"逐元素写样式"

浏览器 `Cmd+A` / `Cmd+C` 复制网页正文时：

1. **不会携带 `<head><style>`**——只复制选区内的 DOM；
2. **可能丢弃最外层容器**——只写在 `<body>` 或根 `<div>` 上的样式会随之丢失；
3. **公众号后台会再清洗一遍 HTML 和 CSS**——即使样式被复制过来，也可能被删。

结论：可见样式必须写在**每一个** `<p>`、`<h2>`、`<h3>`、`<blockquote>`、`<ul>`、`<ol>`、`<li>`、`<pre>`、`<code>`、`<hr>` 自己的 `style` 属性上。列表要给容器和每个 `<li>` 都写。

## 二、禁用清单

| 禁用 | 原因 |
|---|---|
| `<style>` 标签 | 复制不带走 |
| `class` / `id` 选择器 | 依赖 `<style>`，同上 |
| `:before` / `:after` | 后台清洗伪元素；原设计里的装饰要改写成边框或留白 |
| 外链 CSS / 字体 / 图片 / `<script>` | 被清洗，且引入不可控依赖 |
| `@import` | 同上 |
| `background-image`、渐变、阴影 | 被清洗。真正的底纹只能靠后台"全文背景"设置（见下） |
| `hover`、动画、`position:fixed` | 公众号内不稳定或直接无效 |
| JavaScript | 不支持 |
| 只靠父级继承的样式 | 根容器可能被丢弃 |
| 依赖最外层容器才成立的整体边框/背景 | 同上 |

推荐使用的属性子集：`font-family`、`font-size`、`font-weight`、`line-height`、`color`、`background-color`、`margin`、`padding`、`border`、`border-left`、`border-bottom`、`text-align`、`border-radius`、`letter-spacing`。

## 三、底纹的真相（最容易白费功夫的地方）

**结论：任何 CSS 画的底纹（方格、横线、点阵）都带不进公众号正文。**

- 公众号后台会清洗 `background-image`、渐变和 data URI；
- 编辑器的"全文背景"是**编辑器侧的功能**，不是粘贴内容的一部分——它支持纯色，也支持上传自定义图片做平铺底纹；
- 第三方排版工具（96、壹伴、小墨鹰等）的"格子底纹背景"，本质也是替你在后台设置背景图，而不是把底纹写进 HTML。

因此本工具把底纹分两层：

| 层 | 实现方式 | 粘贴后 | 命令 |
|---|---|---|---|
| 结构底纹 | 行内边框模拟：`ruled` 每段一条细底线；`grid` 分节区块带边框 + 内部段落底线 | 保留 | `--bg ruled` / `--bg grid` |
| 画面底纹 | 生成可平铺 PNG，去后台「背景 → 自定义上传」手动设置 | 需手动 | `scripts/make_bg_tile.py` |

**工作流建议**：正文用 `--bg plain`；要底纹效果时，用 `--bg ruled` 或 `--bg grid` 拿到"看起来有纸感"的结构底纹；若一定要真方格纸，再上传 `assets/` 里的 tile 图当全文背景。

## 四、已知回落项（会变、但不致命）

| 项 | 粘贴后表现 | 处理 |
|---|---|---|
| 页面底色（`<body>` 的 `background-color`） | 大概率回落成白底 | 接受白底；或在后台「背景」里设全文背景色 |
| `border-radius` | 通常保留；后台版本不同可能被抹平 | 圆角只做修饰，不承担信息层级 |
| `letter-spacing` | 通常保留 | 眉题/图注的大字距可保留 |
| `<table>` 布局 | 一般保留，是公众号里最稳的图文并排方案 | 头部卡片、编号分节都用表格实现 |
| 通栏元素（负外边距） | 负边距可能被清洗，退化成缩进块 | 本工具不依赖负边距做结构 |
| 图片 | 不内嵌，只输出占位文字 | 粘贴后在原位插入图片、删掉占位框 |

## 五、交付前自检清单

```bash
python3 scripts/generate.py article.md --style all --bg <mode> --check
```

自检脚本覆盖：

1. 不含 `<style>`
2. 不含 `class=` / `id=`
3. 不含 `:before` / `:after` / `<script>` / 外链 / `@import`
4. 不含正文一级标题（避免与后台标题重复成双标题）
5. 不含字面转义残留（`\n`、`%%` 等）
6. 每个 `style` 属性内无重复声明（部分后台会丢弃整条声明）
7. 每个可见元素（`p` / `h2` / `h3` / `blockquote` / `li`）都带 `style`

任何一项不通过，就不要交付。

## 六、与本工具无关但常被问到的两件事

- **自动推送到草稿箱**：需要公众号 API（`draft/add`、`freepublish/submit`），官方标注"仅认证账号"。**未认证的个人订阅号无法调用**（返回 `48001 api unauthorized`），个人主体也无法做微信认证。企业认证号不受影响。
- **用 cookie 模拟后台操作**：违反微信"自动化操作"条款，有封号风险，且 cookie 过期需重新扫码，无法无人值守——不推荐。
