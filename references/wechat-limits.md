# 微信粘贴红线与已知回落项

本文件记录的事实来自 2026-09 的实测与官方文档核查（微信公众号图文编辑器）。规则会变，遇到反例以你的实测为准，并回来更新本文件。

---

## 一、为什么必须"逐元素写样式"

浏览器 `Cmd+A` / `Cmd+C` 复制网页正文时：

1. **不会携带 `<head><style>`**——只复制选区内的 DOM；
2. **可能丢弃最外层容器**——只写在 `<body>` 或根 `<div>` 上的样式会随之丢失；
3. **公众号后台会再清洗一遍 HTML 和 CSS**——即使样式被复制过来，也可能被删。

结论：可见样式必须写在**每一个** `<p>`、`<h2>`、`<h3>`、`<blockquote>`、`<ul>`、`<ol>`、`<li>`、`<pre>`、`<code>`、`<hr>` 自己的 `style` 属性上。列表要给容器和每个 `<li>` 都写。

## 二、禁用清单

| 禁用 | 原因 |
|---|---|
| `<style>` 标签 | 复制不带走 |
| `class` / `id` 选择器 | 依赖 `<style>`，同上 |
| `:before` / `:after` | 后台清洗伪元素；原设计里的装饰要改写成边框或留白 |
| 外链 CSS / 字体 / 图片 / `<script>` | 被清洗，且引入不可控依赖 |
| `@import` | 同上 |
| `background-image`、渐变、阴影 | 被清洗。真正的底纹只能靠后台"全文背景"设置（见下） |
| `hover`、动画、`position:fixed` | 公众号内不稳定或直接无效 |
| JavaScript | 不支持 |
| 只靠父级继承的样式 | 根容器可能被丢弃 |
| 依赖最外层容器才成立的整体边框/背景 | 同上 |

推荐使用的属性子集：`font-family`、`font-size`、`font-weight`、`line-height`、`color`、`background-color`、`margin`、`padding`、`border`、`border-left`、`border-bottom`、`text-align`、`border-radius`、`letter-spacing`。

## 三、背景的真相：三层，不是两层（2026-09-11 关键修正）

先记住一句话：**编辑器底层是 ProseMirror，它的白名单里有 `<section>`，没有 `<body>` 和 `<div>`。**

由此推出三条硬结论：

| 元素 | 粘贴后 | 后果 |
|---|---|---|
| `<body>` 上写 `background-color` | **必丢** | body 根本不在复制范围内（只复制选区 DOM） |
| `<div>` 包住内容 | **内容连同背景被整段吞掉** | div 不在白名单，只剩里面的文字，表现为"整篇样式全没了" |
| `<section>`（内部元素）带 `background-color` | **保留** | 头部卡片、金句卡、引用块的背景靠这个存活 |

**但是——最外层容器会被丢弃（2026-09-11 二次实测推翻 1.1.0 结论）**：

1.1.0 曾把整篇内容包进一个外层 `<section>` 承载全文底色，真机实测**失败**：粘贴后顶部卡片背景还在、全文底色还是白的。结论修正为——**编辑器粘贴时会丢弃/解包最外层容器**，无论它是 `section` 还是别的。全文底色没有任何可靠的粘贴手段，**全文必须按白底设计**；彩色背景只用在内部元素上。

（教训：第一次实测"卡片背景保留、全文底色丢失"时，把原因归给"body 不在复制范围"，推论出"外层 section 能承载"。第二次实测证明外层容器同样被丢弃。对微信行为的结论，每一层都要真机验证，不能从白名单规则外推。）

### 画面底纹仍然带不进去，且公众号后台没有上传入口

**任何 CSS 画的底纹（方格、横线、点阵）都带不进公众号正文。**

- 后台会清洗 `background-image`、渐变和 data URI；
- 第三方排版工具（96、壹伴、小墨鹰等）的"格子底纹背景"，本质也是替你在后台设置背景图，而不是把底纹写进 HTML；
- **2026-09-11 实测：微信公众号后台编辑器没有「全文背景 / 背景图片上传」入口**（只有文字底色），所以"生成 PNG 去后台上传"这条路对公众号走不通。`make_bg_tile.py` 保留给支持自定义背景上传的第三方编辑器。

因此本工具把背景分三层：

| 层 | 实现方式 | 粘贴后 | 怎么做 |
|---|---|---|---|
| **全文底色** | 无可靠手段 | **必丢** | 全文按白底设计；`--page-bg` 仅实验性保留 |
| 结构底纹 | 行内边框模拟：`ruled` 每段一条细底线；`grid` 分节区块带边框 + 内部段落底线 | 保留 | `--bg ruled` / `--bg grid` |
| 画面底纹 | 生成可平铺 PNG | 需编辑器支持背景上传 | `scripts/make_bg_tile.py`（公众号后台无此入口，仅适用第三方编辑器） |

**工作流建议**：默认 `--bg plain` 白底；要纸感时用 `--bg ruled` / `--bg grid` 拿到结构底纹——这是唯一能落地的底纹方案。

## 四、已知回落项（会变、但不致命）

| 项 | 粘贴后表现 | 处理 |
|---|---|---|
| 全文底色（任何承载方式） | **必丢** | 全文按白底设计；彩色背景只用于内部元素（卡片/金句卡/引用块） |
| `background-image`（含 data URI） | 必被清洗 | 别指望它 |
| `border-radius` | 通常保留；后台版本不同可能被抹平 | 圆角只做修饰，不承担信息层级 |
| `letter-spacing` | 通常保留 | 眉题/图注的大字距可保留 |
| `<table>` 布局 | **会被转成编辑器自己的表格组件**：出现边框、列宽错乱（实测两列布局的编号和标题被拉开很远） | 布局一律不用表格；唯一例外是头部卡片的图文并排（实测正常，已补 `border=0` 等属性） |
| 最外层容器 | **被丢弃/解包** | 不依赖外层容器承载任何样式 |
| 通栏元素（负外边距） | 负边距可能被清洗，退化成缩进块 | 本工具不依赖负边距做结构 |
| 图片 | 不内嵌，只输出占位文字 | 粘贴后在原位插入图片、删掉占位框 |

## 五、交付前自检清单

```bash
python3 scripts/generate.py article.md --style all --bg <mode> --check
```

自检脚本覆盖：

1. 不含 `<style>`
2. 不含 `class=` / `id=`
3. 不含 `:before` / `:after` / `<script>` / 外链 / `@import`
4. 不含正文一级标题（避免与后台标题重复成双标题）
5. 不含字面转义残留（`\n`、`%%` 等）
6. 每个 `style` 属性内无重复声明（部分后台会丢弃整条声明）
7. 每个可见元素（`p` / `h2` / `h3` / `blockquote` / `li`）都带 `style`
8. 不含空的 CSS 声明（形如 `background-color:;`）

任何一项不通过，就不要交付。

## 六、与本工具无关但常被问到的两件事

- **自动推送到草稿箱**：需要公众号 API（`draft/add`、`freepublish/submit`），官方标注"仅认证账号"。**未认证的个人订阅号无法调用**（返回 `48001 api unauthorized`），个人主体也无法做微信认证。企业认证号不受影响。
- **用 cookie 模拟后台操作**：违反微信"自动化操作"条款，有封号风险，且 cookie 过期需重新扫码，无法无人值守——不推荐。
